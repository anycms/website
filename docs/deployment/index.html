部署

把构建产物 public/ 部署到任意静态托管

AnyCMS SSG 输出的是纯静态文件（默认 public/），可以部署到任何静态托管服务。

构建生产产物

anycms build            # 渲染 Markdown、编译 Sass、转译 TS、压缩 HTML

产物全部在 output_dir（默认 public/）下，包含：

  • index.html 及所有页面 HTML（已压缩）
  • main.css / main.js
  • rss.xml / atom.xml / sitemap.xml / robots.txt
  • static/ 原样拷贝的文件

常见部署目标

平台做法
GitHub Pages把 public/ 推送到 gh-pages 分支或用 Actions 上传 artifact
Netlify / Vercel构建命令 anycms build，发布目录 public
Cloudflare Pages同上，构建命令指向 anycms build
自建 / Nginx把 public/ 拷贝到 web 根目录
S3 + CloudFrontaws s3 sync public/ s3://<bucket> --delete

base_url

部署前确认 site.kdl 的 base_url 指向最终域名——它影响绝对链接、feeds 与 sitemap 中的 URL。

部署到子路径（如 https://user.github.io/repo/）时，需要相应调整 base_url 与资源路径策略。

CI 建议

在 CI 中运行质量门后再部署：

cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo build --workspace --all-targets
anycms build              # 站点构建本身也应零错误退出

设置 ANYCMS_PLUGIN_STRICT=1 可让任何插件 hook 错误中止构建，避免静默发布坏页面。
